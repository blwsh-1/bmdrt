# BM-DRT 面板界面外壳规范（v0.1 草案 · 待评审）

**日期**：2026-11-12　**状态**：草案，未冻结；本轮**未修改任何代码**。

**缘起**：现有 `dashboard.html` 被评价为"不像拟合软件，缺少明确的任务栏"。本文把需求拆成界面外壳规范，供评审后再决定是否实施。

## 0. 边界与优先级

| 项 | 规定 |
|---|---|
| 约束对象 | 仅 `bm_dash.py` 生成的 `dashboard.html`（页面 HTML/CSS/JS） |
| 不约束 | `bm_result.py`（`payload()`）、`bm_figure.py`（出版图）、`bmdrt.py` 及算法层 |
| 上位文档 | `BMDRT_RESULT_AND_FIGURE_DESIGN.md`（v1.1 决策记录，§3 为 v1.2 布局图） |
| 冲突处理 | **与上位文档冲突时以上位文档为准**；本规范只增补"应用外壳层"，不重开已冻结的布局与口径 |
| 本轮交付 | 仅本文件 + `docs/INDEX.md` 索引行；代码零改动 |

上位文档 §9 已明确"**不在面板里做拟合、选 K、改门禁——它是只读的展示层**"。因此本规范中的"任务栏"是**结果状态的可视化**，不是动作入口；这一条是本规范的红线。

## 1. 现状诊断

现有 DOM（见 `results/AZ31-4Li_100/dashboard.html`）：`#hdr` 内 `.tb`（标题 + `#chips` + `.tools` 三控件）与 `#tabs`（两页签）；正文 `#kpis`、`#opshint`、`.workspace`（`#side` 320px 左控制台 + `#grid` 12 栅格）、抽屉、`#foot`。

| 问题 | 依据 |
|---|---|
| 所有信息都是"已算完的结果"，没有任务/流程概念 | 页签只有"分析 / 数据表"两种内容分区 |
| 结论被拆散在三处，需自行拼合 | KPI 条、左栏判定区、footer 口径文字 |
| 工具入口不成组 | 主题 / 导出 / 重置三个控件散在标题右侧，既非菜单也非工具栏 |
| 无状态栏 | 数据源、spec 版本、警告数、当前投影散在 footer 长文里 |
| 以 AZ31-4Li_100 为例 | `acf=0.909` 未过阈值、`kk.status=warn`，现状需读三处才能判断"结果能不能用" |

**定位决议（待确认）**：保持"单谱、只读、一次生成、离线可开"的结果查看器形态（上位文档 §10 已知限制 1）。不做多谱工程树，不在面板内跑拟合。

## 2. 与已冻结决策的兼容矩阵

实施时最容易踩的四条，逐条锁定：

| 上位条款 | 约束 | 本规范的处置 |
|---|---|---|
| §3 v1.2「主图上方切投影」、`dash_smoke.js` ⑤ 断言 `fitCard.innerHTML` 必须含 `data-mtab="bode"` | 投影 tab 属于 `fit` 卡 | **投影切换保留在卡片内，不上提工具栏**。工具栏只放视图级动作（切页、复位缩放、导出、主题） |
| §9「不在面板里做拟合」 | 面板只读 | "打开数据 / 重新拟合"不进 HTML。若 P1 需要，由**桌面外壳**持有动作，生成新 HTML 后刷新；面板本体不发起计算 |
| §5「判定分两层陈述」、§9「不做可信度总分」 | 禁止合并 | 步骤条是**并列状态点**，禁止"总体完成度 / 进度百分比 / 可信度总分 / 一个总灯"；采样档与结构判据必须分列两步 |
| §4「判定状态色」、`dash_smoke.js` ③ 断言 | 四态类名 | 复用 `pass / warn / fail / na`（注意 `kk.status=ok` → 类名 `pass`），绿/琥珀/红/灰；**不用颜色表达重要性**，不引入第五种状态色 |

另：`dash_smoke.js` 共 **12 项**断言（5 项渲染冒烟 + freq-map / kk-state / rwp-neutral / pages / text+spec / export-drawer / phase-resid），改 JS 后必须全过。`test_contract.py` F1–F7 约束的是数据层，本规范不改 `payload()`，预期不受影响。

## 3. 五层信息架构

```
L1 菜单栏     产品名 · 菜单组 · 右：样品名 / 只读标记          [新增行]
L2 标题工具栏 样品名 · 判定 chips · 成组工具按钮               [改造现有 .tb]
L3 任务状态条 6 个并列状态点，只读                            [新增行]
L4 页签       分析 / 数据表（保留，#page= 深链）                [不动]
──────────────────────────────────────────────────
L5 工作区     左控制台 #side + 右 12 栅格 #grid               [不动，v1.2 冻结]
──────────────────────────────────────────────────
L6 状态栏     数据源 / spec / 警告数 / 当前视图 / 就绪          [新增，footer 上方]
   页脚       Rwp 定义、区间口径、判定说明、σ 说明              [不动]
```

**L1 菜单栏**：P0 只出现**真实可执行**的菜单组——视图（切页、切投影、复位缩放、面板显隐）、报告（导出…、单面板 SVG、布局模板）、帮助（快捷键、口径说明、关于）。**不渲染"文件 / 拟合 / 编辑"三个空组**：静态 HTML 下它们没有真实动作，做成禁用项是负体验。P1 由桌面外壳提供完整原生菜单（文件/编辑/视图/拟合/分析/报告/帮助）。

**L2 工具栏**：把现有 `主题 / 导出… / 重置` 收编成组，补"复位缩放"与"切页"，按 数据无关｜视图｜输出 分组，组间竖线分隔。不放"打开数据 / 重新拟合"。

**L6 状态栏**：只放短字段，`#foot` 的口径长文原样保留，不搬进状态栏。

**L4 与 L3 的关系**：页签是**内容分区**，任务状态条是**结果状态**，两者不合并。为避免看成两套导航，状态条视觉上不用 tab 样式（无下划线、无色块、无边框），只用小圆点 + 文字 + 细分隔。

## 4. 任务状态条（核心）

### 4.1 语义

步骤条表示"**这一次分析各环节的结论**"，不是"流程进行到哪一步"。分析早已结束，因此**不设当前步、不设进行中、不设进度**；点击某步只改变"看哪里"，不改变任何数据。

### 4.2 六步与字段映射

字段全部取自已核实的 `payload()` 顶层键，不新增数据源：

| # | 步骤 | 状态来源 | 判定规则 |
|---|---|---|---|
| 1 | 数据 | `n`, `f_min`, `f_max` | 三者有效且 `n>0` → `pass`；否则 `na`。**不判数据质量** |
| 2 | KK 校验 | `kk.status`, `kk.reason` | `ok→pass` / `warn→warn` / `fail→fail` / `unavailable→na`；tooltip 取 `kk.reason`，四态文案沿用 ③ 断言 |
| 3 | DRT / 模型 | `K`, `include_L`, `comparison`, `candidates`, `drt` | 有 `K` 且曲线/DRT 可用 → `pass`。`comparison=false` 时 tooltip 写"未做跨 K 比较"，**不算 fail、不显示 `elpd_diff=0.0`**（§5） |
| 4 | 拟合 | `verdict.sampling_level`, `verdict.grade`, `checks[rhat]`, `checks[div]` | 采样降级（`grade≤1`）或 R̂/div 未过 → 对应态；全达标 → `pass`。只讲采样档 |
| 5 | 判定 | `verdict.level`（`ok/bad/warn`）, `checks`, `warnings`, `verdict.structure_pass/structure_total` | 直接映射；tooltip 给"结构判据 n/3"与警告条数。只讲结构判据，与第 4 步分开陈述 |
| 6 | 报告 | **无载荷字段** | P0 固定 `na`，文案"出图状态不在面板载荷内" |

第 4/5 步的划分直接对应 §5「采样档 + 结构判据两层陈述」，不是人为拆细。

### 4.3 禁止项

- 不显示"完成度 / 百分比 / 总分 / 综合评级"（§9）。
- 不用颜色表达重要性（§4）；状态点只表达四态结论。
- 不由前端推断状态：不得 `fetch` 同目录 `manifest.json`（`file://` 下会被 CORS 拦），不得根据"导出按钮是否被点过"伪造第 6 步状态，不得自造"通过/未通过"。
- 若 P1 要显示真实出图状态，由 `bm_dash.build()` 从 `manifest.json` **注入只读字段**，而非前端读取；该改动会触及 `SPEC_VERSION` 与 F4/F7，须单独立项。
- 不新增抽屉类型。点击步骤优先复用现有视图与 `#detail=` 抽屉，避免影响 ⑦ 断言。

### 4.4 点击行为

| 步骤 | 行为 |
|---|---|
| 1 数据 | 滚动/高亮左栏「数据」区块 |
| 2 KK 校验 | 滚动/高亮左栏「判定」区块（KK 本就在 `renderSide()` 里） |
| 3 DRT / 模型 | `#page=md`（数据表页）或 `#detail=drt` |
| 4 拟合 | `#page=ov&detail=fit` |
| 5 判定 | 滚动/高亮左栏「判定 / 警告」区块 |
| 6 报告 | 打开导出抽屉 `openExport()` |

深链格式保持 `#page=<id>&detail=<id>`，不新增参数。点击后 `JSON.stringify(D)` 必须逐字不变。

## 5. 布局与视觉规格

### 5.1 垂直预算（硬约束）

新增层会吃掉主图空间，v1.2 里"Nyquist 跨两行、首屏看全"的理由仍然成立：

| 层 | 现状 | P0 后 | 增量 |
|---|---|---|---|
| 菜单栏 L1 | 0 | 26px | +26 |
| 标题工具栏 L2 | ~54px | ~54px | 0（改造，不新增行） |
| 任务状态条 L3 | 0 | 30px | +30 |
| 页签 L4 | ~30px | ~30px | 0 |
| 状态栏 L6 | 0（在 footer） | 24px | +24 |
| 合计 header | ~96px | ≤140px | ≤+44 |

- 1560×900 下 `#hdr` 总高 ≤140px，且 `fit` 卡上沿 ≤400px（保证首屏能看见完整 Nyquist 圆弧）。
- `syncHdr()` 靠 `offsetHeight` 动态写 `--hdrtop`，**逻辑不改**即可自动跟随；但 `dash_smoke.js` 的 DOM 桩把 `offsetHeight` 写死 96，若断言依赖该值需同步核对。
- 状态栏放 `footer` 上方且**不 sticky**，避免再压一层固定区域。

### 5.2 响应式（沿用现有 1240 / 1100 / 1080 断点）

- ≤1240px：菜单栏折成单个「菜单」按钮（下拉），任务状态条横向可滚动，状态栏只保留 数据源 / 警告数 / 当前视图 三项，`#hdr` 目标 ≤110px。
- ≤1080px：状态条仍单行可滚，不换行堆高；左栏按 v1.2 折成横排，主图通栏、DRT 与残差各半的规则不变。

### 5.3 样式

- 只复用现有 CSS 变量 `--fg/--sub/--line/--ok/--warn/--bad/--radius/--gap` 与 `THEMES` 注入的 `--accent`，**不引入新色板**；状态点复用 `.chk .dot` 的 `pass/warn/fail/na` 规则。
- 字号：菜单 12px、工具栏 12px、状态条 11.5px、状态栏 11px，**不低于 11px**。
- 主题预设只改排版语言，不改状态语义色（§4、§10.4）。
- 新增层不使用渐变、阴影、色块导航；与现有极简风格一致。

## 6. 数据与契约不变量

以下 id、函数签名与输出语义**必须原样保留**，否则 `dash_smoke.js` 立即失败：

- DOM id：`#hdr #ttl #sub #chips #tabs #kpis #opshint #side #grid #foot #mask #drawer #db #dt #dclose #tip #theme #btn-exp #btn-reset`。
- 函数：`renderChrome()`、`renderSide()`、`renderTabs()`、`setPage()`、`openExport()`、`renderFit/Drt/Resid/Bode/ReIm()`、`drawModel()`、`specForFigure()`、`togglePin()`、`pinIdx()`、`renderReadout()`、`syncHdr()`。
- 断言相关事实：`#grid` 卡片数 ov=3 / md=1；`fit` 卡内含 `data-mtab="bode"`；`#kpis` 中 Rwp 单元不带 `kpi pass|warn|fail`；`md` 页 `#kpis` 隐藏；Lin-KK 四态类名 `pass/warn/fail/na` 与文案「通过/警告/未通过/不可评价」。
- 常量 **`PAGES` / `DEFAULT_PANELS` / `PANEL_META` / `DEFAULT_LAYOUT` 的 id 序列不动**（变了会触发 `loadLayout()` 回默认，清掉用户版式）。
- `localStorage` 键、`LAYOUT` 结构、`#page=` / `#detail=` 深链、导出 `figure_spec.json` 内容不变。
- 新增 DOM id 只用 `#menubar / #steps / #statusbar`，不占用现有 id。

| 期 | 内容 | 前提 |

**关于"要不要等打包时再做"的结论**：不等。任务栏定的是信息架构，后续所有图、表、导出都要往这个骨架挂；等到打包再改，等于把已定稿的 KPI、四张卡、抽屉、主题、导出全部重排一次。但 P0 只做**纯前端外壳**，真动作确实必须等宿主，两者不冲突。
