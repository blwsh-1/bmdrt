# M-b 判据的外部数据检验：A ⊂ B 是 AZ31 特有的假象

> 2026-11-22。起因：用户指出「AZ31 数据太差」，不能用它同时当发现和证据。
> 本轮用 `out/batch21/results.json` 里**非 AZ31 的 18 条谱**做独立检验，**推翻了
> `ACF_BAND_PROFILE.md` 同日早些时候的一个结论**。

## 0. 被推翻的结论

`ACF_BAND_PROFILE.md` §0/§7 之前写过（同时进过 `INDEX.md` 与当日日志）：

> M-b 名义上是两条判据的合取，实测 **acf 通过的 4 条全在改善通过的 6 条之内**（A ⊂ B），
> 所以「改善 ≥ 0.20」在 §14 上从未独立起作用，**M-b 实际退化为单条绝对阈值**。

这句话在 §14 的 14 条 AZ31 谱上**是对的**，但把它当成 M-b 判据的一般性质是错的。

## 1. 独立数据

`out/batch21/results.json`，21 条谱、每谱并列 6 个候选（voigt / nested / adr），
每个候选带 `topology` / `config` / `acf` / `rms` / `rhat` / `div`。这是现成的
**同一谱上 voigt + nested 双族 acf**，不需要重跑拟合。

去掉 3 条 AZ31，剩 **18 条**：合成 3、腐蚀 3、钝化 3、涂层 3、2E 3、3E 3。

预算是 `quick`（不是 §14 正式档），nested 有 `layers=1/2`、`include_L=True/False`
四种配置。为避免“取族内最优”的选择偏差，分别按固定配置检验；有完整
`layers=1/2` 且 `include_L=False` 的是 **12 条**。

## 2. 结果：两条判据在外部数据上是真正独立的

| 固定配置 | n | A: `acf≤0.50` | B: `改善≥0.20` | A ⊆ B ? | A\B | B\A |
|---|---|---|---|---|---|---|
| nested `layers=1` | 12 | 3 | 0 | **否** | 3 | 0 |
| nested `layers=2`（§14 同配置） | 12 | **4** | **2** | **否** | **3** | **1** |

`layers=2` 的 12 条里：

- **acf 达标但改善不够的 3 条**：`acf/改善` = 0.348/0.086、0.385/−0.022、
  0.403/0.020 —— 这几条 voigt 基线本来就低（腐蚀类 0.36–0.45），
  nested 再低也不构成“比 voigt 好 0.20”。
- **改善够但 acf 不达标的 1 条**：涂层 0.552/0.295 —— 它在 AZ31 式中会被
  `acf≤0.50` 挡掉，说明这一条确实在独立起作用。

⇒ **在外部数据上，`acf≤0.50` 与 `改善≥0.20` 是两条互相独立的约束。**
AZ31 上的 A ⊂ B 不是判据的性质，是样本的性质。

## 3. 为什么 AZ31 上会退化

AZ31 的 **voigt 基线 acf 高度一致且都很高**（14 条落在 0.730–0.940，跨度 0.21）。
只要 nested 把 acf 压到 0.50 以下，相对改善必然 ≥ 0.23 —— B 被 A 自动蕴含。

外部数据的 voigt 基线跨度大得多（0.304–0.936，跨度 0.63），其中腐蚀类只有
0.36–0.45。所以“acf 低”不再意味着“比 voigt 好很多”。

> **结论：M-b 的两条判据设计本身没有冗余问题；是 AZ31 这批谱的 voigt 基线太齐，
> 让其中一条在事后看起来像空判据。**

## 4. 什么没有被推翻

`MB-SIM-01`（80 条模拟盲测，类型 C 模型不足）给出 `AUC(B vs C) = 0.517`
[0.36, 0.68]。那是**模拟数据上 acf 对“仪器寄生 vs 样品侧结构”的区分力**，
与 AZ31 无关，**仍然成立**。

所以两件事要分开：

| 问题 | 结论 | 数据来源 |
|---|---|---|
| M-b 的两条判据是否互相冗余？ | **不冗余**（本轮推翻 AZ31 的假象） | batch21 外部 12 条 |
| acf 能否区分残差来源？ | **不能**（AUC 0.517） | MB-SIM-01 模拟 80 条 |
| AZ31 的 4/14 是否可复现？ | **是**，两套口径都是 4/14 | 正式档 14 条 |

⇒ M-b 的问题不在“写成了一条”，而在**它测的量（残差白不白）和它想问的问题
（是否捕获真实结构）不是一回事**。这一条不受本轮影响。

## 5. 局限（必须写明）

1. **预算不同**：batch21 是 `quick`，§14 是正式档 2000/1000/2/ta0.98。
   acf 的绝对值不可跨预算比较；本轮只检验两条判据的**集合关系**，不比较通过率。
2. **n=12**（`layers=2` 固定配置）。A\B 3 条、B\A 1 条，方向明确但样本小。
3. **谱本身质量参差**：合成/涂层在 11-21 已被判“基准不合格”；真正干净的
   只有 2E/3E（各 3 条在 batch21 里）。所以本轮是**判据结构检验**，
   不是“在干净数据上重做验收”。
4. **没有重跑**：全部来自已落盘产物，属只读复核。

## 6. 要做成真正的外部验证，还差什么

`out/2E_full/` 有 117 条、`out/3E_full/` 有 138 条，先验审计已证
**这 255 条的 σ 距全部 < 2.5**（数据干净）。但它们的单条产物只有 voigt 一族，
没有 nested 对照 ⇒ **做不了 M-b**。

要补的是：在这 255 条中选一个有代表性的子集（建议 2E/3E 各 20 条），
用同一预算跑 voigt + nested 双族，算 `acf` 与相对改善，检验：

- A ⊆ B 是否系统性不成立（本轮的 12 条是否已经足够）；
- acf 的分布是否双峰（AZ31 是双峰，外部 18 条是连续谱 0.187–0.941）；
- 低频截断的方向模式（通过组变差、失败组变好）是否复现。

这是**要跑拟合的一步**，成本可控（quick 档每条几秒），但按规矩先授权。

## 7. 复现

```bash
D:/autoeis_env/Scripts/python.exe - <<'PY'
import json
d = json.load(open('out/batch21/results.json', encoding='utf-8'))
rows = d['rows'] if isinstance(d, dict) else d
for r in [x for x in rows if x['class'] != 'AZ31']:
    by = {}
    for c in r.get('cands') or []:
        by.setdefault(c['topology'], []).append(c)
    v = by['voigt'][0]['acf']
    n = [c for c in by['nested'] if c['ok']
         and c['config']['layers'] == 2
         and not c['config']['include_L']][0]['acf']
    print(r['class'], 'A=', n <= 0.50, 'B=', v - n >= 0.20)
PY
```
