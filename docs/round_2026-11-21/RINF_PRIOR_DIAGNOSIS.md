# `R_inf` 先验定标缺陷：高动态范围谱为何被判"拟合失败"（2026-11-21 诊断）

> 性质：**诊断**，不是修复记录。修法已验证但**未改内核**（见 §5 待裁决）。
> 触发：21 条跨类拟合测试里，腐蚀/钝化/涂层的 `rms_rel` 出现 110%–2572%。
> 脚本：`diag_metrics.py`、`diag_rinf.py`（本目录，可复跑）。

## 1. 现象

21 条（7 类 × 3）按 `quick` + `free` 跑三族默认候选，合成/2E/3E 正常（0.00–1.7%），
腐蚀/钝化/涂层全部崩：

| 谱 | 最佳候选 | `rms_rel` |
|---|---|---|
| 腐蚀 #1 | voigt K=1 | 110.4% |
| 腐蚀 #2 | nested L=2 | 536.3% |
| 腐蚀 #3 | nested L=2 | 287.4% |
| 钝化 #1 | nested L=2 | 2572.7% |

## 2. 排查：先排除三个"看起来最像"的原因

| 猜测 | 检验 | 结论 |
|---|---|---|
| 预热预算不够（`BUDGETS["quick"]`=300，`SEL.QUICK`=800） | 300 与 800 各跑一次 | **不是**：两者都给 1.97%（全局口径） |
| `sigma_floor` 改了似然 | `SEL.SIGMA_FLOOR = 0.0` | **不是**，透传即关闭 |
| `likelihood="free"` 与直接调用不同 | 两者都 `sigma=None` | **不是**，同一条路径 |

## 3. 真因一：`rms_rel` 是**逐点相对**口径，不是全局归一

同一条曲线（`Zm` 完全相同）用两种口径算：

| 口径 | 值 |
|---|---|
| `SM.metrics(...)["rms_rel"]` | **110.392%** |
| `100·√(mean\|Δ\|²)/√(mean\|Z\|²)`（全局） | **1.964%** |

差 56 倍。原因：该谱 `|Z|` 从 1424 Ω（高频端）到 2.58e6 Ω（低频端），
**动态范围 1812 倍**。逐点相对口径下，高频段每个点的分母只有 1e3 量级，
模型在那里偏一点就是几百个百分点；低频段分母 2.5e6，同样的绝对误差只占 0.3%。

**所以 110% 是真实读数，不是 bug。** 项目的 `rms_rel ≤ 5%` 验收线本来就是
逐点相对口径（对小阻抗段不放水），这一点是对的。但由此得到一个推论：
**现有数字里凡是"全局好、逐点差"的谱，都被逐点口径如实地判成了不合格。**

## 4. 真因二：`R_inf` 的先验定标用错了参照量

`bm_core.make_model` / `bm_top._prior_table` 里：

```python
R_inf: LogNormal(log(0.2 * zmax), 1.0)      # zmax = max|Z|
```

而 `R_inf` 的物理含义是**高频极限**（电容在高频短路，只剩串联电阻），
参照量应该是 `|Z(f_max)|`，不是 `max|Z|`。腐蚀 #1 的实测：

| 量 | 值 |
|---|---|
| `zmax = max\|Z\|` | 2.58e6 Ω |
| `|Z(f_max)|`（≈ 真值 `R_s`） | 1424 Ω |
| 真值 `R_s` | 1000 Ω |
| 先验中心 `0.2·zmax` | 5.16e5 Ω |
| **先验中心 / 真值** | **362 倍 = 6.2σ**（σ=1.0） |

`LogNormal(log(0.2·zmax), 1.0)` 覆盖真值需要 6.2 个标准差。300 步预热走不到，
NUTS 停在 `R_inf = 9.24e3`（仍偏真值 9 倍）。**高频段因此整体抬高 ~8 kΩ**，
在 `|Z|≈1.4e3` 处就是 550% 的相对误差。

三段 rms 直接指认这一点：

| 配置 | `rms_rel` | bands[低,中,高] | 拟合 `R_inf` |
|---|---|---|---|
| 默认 `0.2·zmax` | 110.24% | [2.0, 8.3, **269.9**] | 9240 Ω |
| `zmax = 2·\|Z(f_max)\|` | 8.75% | [2.1, 8.0, 20.1] | 1010 Ω |
| **`zmax = 5·\|Z(f_max)\|`** | **7.65%** | [2.0, 7.1, **17.5**] | 1230 Ω |
| `zmax = 10·\|Z(f_max)\|` | 15.94% | [2.0, 7.1, 38.5] | 2030 Ω |

**低/中频段一直是 2%/8%（没坏），只有高频段从 269.9% 掉到 17.5%。**
`R_inf` 也从 9240 落到 1230（真值 1000）。

## 5. 影响面（21 条实测）

按 `0.2·zmax / |Z(f_max)|` 折算成 σ 数（σ=1.0）：

| 类 | σ 数 | 是否卡先验 |
|---|---|---|
| 合成 ×3 | 0.8 / 1.2 / 1.6 | 否 |
| 腐蚀 ×3 | **5.9 / 7.1 / 7.3** | **是** |
| 钝化 ×3 | **10.2 / 8.5 / 10.0** | **是** |
| 涂层 ×3 | **2.6 / 3.2 / 2.7** | **是** |
| 2E ×3 | 0.9 / 1.6 / 1.5 | 否 |
| 3E ×3 | 1.1 / 1.0 / 0.8 | 否 |
| AZ31 ×3 | **3.2** / 1.9 / 1.2 | 1 条是 |

**10/21（48%）落在先验 2.5σ 之外**，与"失败类目"完全重合。
`测试数据/` 的腐蚀/钝化/涂层正是"高阻抗、高动态范围"体系，所以三类全中。

## 6. 修法（最小改动，已验证但未落地）

只改 `R_inf` 一条先验的**参照量**，其余先验、采样、结构不动：

```python
# 现在
R_inf: LogNormal(log(0.2 * zmax), 1.0)          # zmax = max|Z|
# 改为
R_inf: LogNormal(log(0.5 * z_hf), 1.0)          # z_hf = |Z(f_max)|
```

理由：`R_s` 的物理定义就是高频极限，用 `max|Z|` 定标没有任何物理依据——
`max|Z|` 由低频弛豫幅值决定，与 `R_s` 可以差三个数量级。
这不是"调参"，是把先验的参照量换回它该有的量。

**为什么不直接改 `zmax` 全局值**：`zmax` 同时定标 `R1`/`Q`/`W`（这些确实与
弛豫幅值同量级），一起改会把它们的先验缩到错误区间。上面的
`zmax_override=5·|Z|` 之所以有效，是因为 HN 的 `W`/`tau` 有耦合能自己走回来，
但那是运气，不是设计。

## 7. 落地代价（供裁决）

要改的是**冻结层**：`bm_core.make_model` + `bm_top._prior_table`，撞
`test_entry_parity` 的 bm_core/bm_top 语义守卫，需要显式登记。
且改先验会**改变所有既有结果的数值**（凡 `R_inf` 落先验外的谱都会变），
按项目纪律应作为独立一轮、带预注册地做，不能混在"跑个测试"里。

在此之前，21 条测试的**正确读法**是：

> `rms_rel` 高的那 10 条，是"`R_inf` 先验参照量错 + 逐点相对口径"共同放大的
> 结果，**不是模型能力不足、也不是采样失败**——低/中频段始终 2%/8%，
> 把 `R_inf` 定标换对后同预算降到 7.65%。

## 8. 21 条双口径实测（2026-11-21 19:00，quick/free）

为了把"先验错"与"能力不足"分开，每条谱跑**两组**：
`prod`（默认 `zmax=max|Z|`，只 voigt K=1 作对照）与
`fixed`（`zmax_override = 5·|Z(f_max)|`，全部 5 个候选）。
脚本 `batch_fit_21.py`，产物 `out/batch21/results.json`，总耗时 11.3 分钟。

| 类 | n | 生产 rms 中位 | **修正 rms 中位** | 修正 ≤5% | acf≤.50 | R̂≤1.05 |
|---|---|---|---|---|---|---|
| 合成 | 3 | 1.0% | **0.08%** | 3/3 | 1/3 | 0/3 |
| 腐蚀 | 3 | 298.5% | **6.04%** | 1/3 | 3/3 | 2/3 |
| 钝化 | 3 | 2774.6% | **69.15%** | 0/3 | 0/3 | 3/3 |
| 涂层 | 3 | 38.3% | **22.04%** | 0/3 | 0/3 | 0/3 |
| 2E | 3 | 6.4% | **4.10%** | 2/3 | 3/3 | 0/3 |
| 3E | 3 | 1.0% | **0.33%** | 3/3 | 1/3 | 2/3 |
| AZ31 | 3 | 28.9% | **9.82%** | 0/3 | 2/3 | 1/3 |

### 8.1 先验修法确实有效，但**必要不充分**

- **腐蚀**：298.5% → 6.04%（50 倍）。三条都落到 4.6–6.3%，说明这一类
  "只是被先验卡住"，模型能力够。
- **AZ31**：28.9% → 9.82%。`AZ31-4Li_150` 从 111.7% → 11.2%。
- **2E / 3E / 合成**：本来就在先验内，改善小（3E 1.0→0.33），符合预期。

但下面两类**修了先验仍然差**，说明还有别的原因：

- **钝化 69.15%**（三条 68.5 / 69.2 / 69.4，**高度一致**）：
  高频段仍 91–95%。这种"三条几乎同一个数"的模式说明不是采样噪声，
  而是**结构性系统偏差**。钝化真值是 `[P1,P2-R3]-R4`——**3 个 CPE + 2 个 R**，
  而 voigt(K≤2) / nested(L≤2) 最多 2 个弛豫单元，表达不了。
- **涂层 22.04%**（10.3 / 22.0 / 27.8，离散大）：真值
  `R1-[P2,R3-[P4,R5-P6]]` 是**双层嵌套 + 5 个 CPE**，同样超出当前族空间。

### 8.2 另一批问题：`R̂` 异常（与先验无关）

修正口径下仍有几条 `R̂` 远超阈值：

| 谱 | 最佳 | rms | **R̂** | div |
|---|---|---|---|---|
| 合成 `ecm_05687_L_R_RCPE` | nested L=2 | **0.00%** | **986.04** | 9 |
| 涂层 #1 | nested L=2 | 22.04% | **53.14** | 1 |
| 涂层 #3 | nested L=2 | 10.25% | **25.98** | 0 |
| 腐蚀 #1 | nested L=2 | 6.31% | **4.30** | 121 |
| 合成 #1 | voigt K=2 | 2.09% | 2.20 | 41 |

`ecm_05687` 尤其刺眼：**rms = 0.00% 但 R̂ = 986**。拟合完美而链间完全不一致
⇒ 后验是发散的、只拟合到一条链的局部模式。这类结果**必须按不可用处理**，
不能因为 rms 漂亮就收。腐蚀 #1 的 `div=121` 同源。

### 8.3 残差结构（acf）普遍不达标

即使 rms 达标的类，`acf ≤ 0.50` 也只有：合成 1/3、3E 1/3、腐蚀 3/3。
这与项目既有结论一致（§14 两次卡 M-b、R27"过 ≠ 残差白"）：
**rms 好不等于结构对**，拟合测试不能只看 rms 排名。

## 9. 本轮结论（三条，按重要性）

1. **`R_inf` 先验参照量错是真的缺陷，且修法便宜**（一条先验、已验证 50 倍改善）。
   但它只解释"腐蚀/AZ31"这一类；**钝化/涂层差是族表达力不足**，与先验无关。
2. **"生产口径会把 48% 的谱判成灾难"这件事本身是可复现的**：同一条谱
   110.39% ↔ 7.65% 的差别只来自 `zmax` 的参照量。任何拿 `rms_rel` 跨类比较的
   结论，在修先验之前都不可靠。
3. **`R̂` 必须与 rms 一起读**：`ecm_05687` 的 rms=0.00% / R̂=986 是本轮最危险的
   一条——它证明"拟合完美"可以完全建立在发散后验上。

## 10. 未做的事

- **没有改内核默认**：`bm_core` / `bm_top` 的 `R_inf` 先验一行未动。上面所有
  "修正"数字都靠 `zmax_override` 从外部传入，默认路径逐位不变（`entry_parity`
  207/207 守着）。
- 没有为钝化/涂层加层数（`layers=3` 或第三个弛豫单元）——那是扩族，需预注册。
- 单 seed、`quick` 预算：`R̂` 异常的条目需要用 `standard` 复核才谈得上结论。
