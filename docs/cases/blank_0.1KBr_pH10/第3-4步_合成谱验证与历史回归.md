## 1. 第 3 步：四个合成用例

### 1.1 数据设计（全部真实跑 NUTS，非逻辑推演）

| 用例 | 谱 | 构造 | KK 状态 |
|---|---|---|---|
| 2 | `U2_noise2` | `bm_core.model_z` 正演**单分量** HN（R∞=20, W=40, f₀=1 kHz, φ=0.8），50 点 0.1–1e5 Hz，注入 **2%** 相对噪声 | `ok`（中段 1.4%） |
| 2b | `U2b_K2` | 正演**双分量** HN（f₀=10 kHz / 1 Hz，各 w=30），0.5% 噪声 | `ok`（中段 0.3%） |
| 4 | `E3` | 现成 `examples/example_caseG_wo_only.csv`（加噪 Wo-only） | **`warn`**（中段 8.5% > 5%，ac1 0.71/0.09 非系统性） |
| 4b | `U4b_warn_K2` | 双分量真值 + 0.5% 噪声 + 中段 1–100 Hz **10% 随机扰动**（非系统性） | **`warn`**（中段 6.8%，ac1 −0.32/−0.48） |

四条都跑 `--krange 1,2 --kk warn`（full 档 3000/1000/3 链，同 seed/先验），输出在 `out/_v2cases/`。

### 1.2 NUTS 实测与状态机输出

| 用例 | elpd K=1 / K=2 | dse | 剔除理由 | v2 `k_selection_status` | `k_reference` |
|---|---|---|---|---|---|
| **2** | −102.7 / −102.7 | 0.3 | K=2：`div=42`（采样不合格） | **`K_SELECTION_AMBIGUOUS`** | 1 |
| **2b** | −317.8 / 25.6 | 7.9 | 无 | **`converged`** | 2 |
| **4** | −205.3 / −111.0 | 5.2 | K=2：R̂=1.669 / bulk=5 / tail=37 / div=81 / 峰位出窗 | **`exploratory_only`** | 1 |
| **4b** | −329.1 / −241.0 | 19.2 | 无 | **`exploratory_only`** | 2 |

**四个用例全部按预期：**

- **用例 2**：Δ=0.1 < 2×dse=0.6，K=2 因 divergences 被剔除 → 候选集合不完整 → 触发
  `K_SELECTION_AMBIGUOUS`。✅
- **用例 2b（反向）**：Δ=343.4 ≫ 2×7.9=15.8 → `converged`(K=2)，**没有**误触发 ambiguous。✅
- **用例 4**：KK `warn` → 只出探索性结果，不写 `converged`。✅
- **用例 4b（关键反向）**：KK `warn` **且** K=2 优势 88.1 > 2×19.2=38.4 →
  仍判 `exploratory_only`，**没有**被写成 `converged`。✅ 这正是「严格门控与诊断报告分开」要防的情形。

### 1.3 用例 2 暴露的一处规格歧义（已修订）

用例 2 里 K=2 因采样不合格被剔除，此时「只有一个可接受候选」按旧 ③ 会走 `not_compared`，
与用户要求的 `K_SELECTION_AMBIGUOUS` 冲突。已在 v2 §4 澄清：

> ③ 只适用于**从一开始就只有一个候选**（强制单 K）；若原本多候选、部分因采样不合格被剔除，
> 属于「候选集合不完整」，不走 `not_compared`，继续到 ⑤ → `K_SELECTION_AMBIGUOUS`。

## 2. 第 4 步：历史回放离线回归

遍历 `out/` 下 **76 条** `real_*.json`（2E 全量、ECM 回归、案例、本轮合成样例），按 v2 规则简化重判，
与旧 `k_selection_status` 对比。结果 `v2_history_regression.csv`（含 `change_reason` 列）。

| 新状态 | 条数 | 性质 |
|---|---|---|
| `not_compared` | 19 | 未变（强制单 K / 无 K 扫描） |
| `converged` | 9 | 未变 |
| **`exploratory_only`** | **42** | 严格门控：`sampling gate` 36 条、`KK gate` 6 条 |
| **`WOULD_CHANGE_K`** | **2** | `peak-out policy change`：本案例两条，v2 ④ 设计意图 |
| **`K_SELECTION_AMBIGUOUS`** | **4** | `K candidate incomplete`：多候选中部分被剔除 |

共 48 条状态变化。按审查意见**降级表述**：

> 76 条历史记录完成了基于现存 JSON 和日志的**简化回放**，未发现明显违背 v2 设计原则的状态变化。
> 由于历史文件未保存所有候选的完整诊断信息，该结果**不等同于逐候选重跑**，也不能替代实际状态机的回归测试。

`change_reason` 四类：`sampling gate` 36 / `KK gate` 6 / `K candidate incomplete` 4 / `peak-out policy change` 2。
42 条 `exploratory_only` 是严格门控的设计结果，不应统计成算法退步。

**回归中修正过一次判定规则**：`example_caseE` 初版被判 `WOULD_CHANGE_K`，但它的剔除理由里含
`R̂=1.667 / bulk=5 / tail=37`（采样不合格），按 v2 应先归到候选不完整而非直接改选 K。
脚本已加入该检查，最终归为 `K_SELECTION_AMBIGUOUS`。

## 3. 局限（必须保留）

1. 历史回归是**简化重判**：`real_*.json` 只存最终选中 K 的结果，不含每个候选的完整诊断；
   剔除理由、Δ、dse 来自日志文本与 JSON 字段。它不是重跑 67 次 NUTS 的结论。
2. 用例 2 的 K=2 在单分量谱上总有 divergences，验证的是**候选不完整分支**；审查意见要求的
   「两个合格候选 + Δ 不显著」正向用例，已用 6 组近简并双峰谱尝试构造但**未成功**（K=2 普遍采样退化，
   加 σ 地板仍只到 grade 1）。详见 `审查意见处理_v2修订.md` §2，该用例仍列为待补。
3. 用例 4/4b 的 KK `warn` 由「中段随机扰动（非系统性）」触发，属于噪声型 warn；
   尚未覆盖「端部超阈 / μ 未收敛」型 warn。
4. `mechanism_identifiability` 的历史值一律 `not_tested`（历史谱都没有完整 `none/Ws/Wo` 对照），
   符合「缺少证据写 not_tested」原则，不需要逐条核对。
