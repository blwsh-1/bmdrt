# 涂层族 Voigt 失效率 pilot：预注册（跑之前固定）

状态：**判据已冻结**。以下阈值在本轮任何拟合结果产出之前写定，跑完不得回改；
若认为阈值不合理，只能在本文件末尾追加"下一轮修订"，不得覆盖本轮判定。

上游：`POWER_AUDIT_SCOPE.md`、`STAGE2_SPEC.md`（未冻结）、本次 6 条试跑（`out/_user_fit_nested/`）。

## 0. 要回答什么

不是"Voigt 好不好用"，而是**生产默认路径**在一个已知拓扑族上的失败率，并把失败拆成三种机制：

| 标签 | 含义 | 改进方向 |
|---|---|---|
| `structural_mismatch` | 采样正常、但残差显著高于该谱噪声底 → 模型族表达不了 | 换/扩族 |
| `init_failure` | 采样本身没收敛，但换合理初值可恢复 | 改初始化 |
| `param_unidentifiable` | 曲线贴到噪声底，但单参数恢复不出来 | 只报组合量 |

三者可以并存于同一族的不同样本，**不得互相顶替**（尤其不能用"改善初始化"掩盖结构不足）。

## 1. 抽样（固定、不看拟合结果）

- 总体：`测试数据/涂层/.../Generated EIS data and Nyquist plots/*.csv`，1000 条。
- 实测该族**只有 3 个参数在变**：`Q_P2`、`R3`、`Q_P4`（各自对数均匀、两两相关 ≈0）；
  其余固定：`Rs=150`、`n_P2=0.9`、`n_P4=0.95`、`R5=1e5`、`Q_P6=1e4`、`n_P6=0.5`。
- 分层 = `Q_P2`（按全体 1000 条的 log 三分位）× `R3`（中位二分）× `Q_P4`（中位二分）= **12 格**，
  每格抽 **5** 条 → **60 条**。
- 格内抽样方法：按 `md5(文件名)` 十六进制升序取前 5。**与拟合结果、与文件名字典序都无关**，
  可逐位复现，且不构成"挑容易的"。
- 落盘抽样清单（文件名 + sha256 + 三联分箱），供第三方复核。

> 不按 `|Z|max` 分层：`|Z|max` 是 `Q_P2` 的单调函数（低频平台），分它等于重复分 `Q_P2`，
> 而会漏掉 `R3`/`Q_P4` 两个真实自由度。

## 2. 口径（每条谱三样都记）

| 项 | 口径 |
|---|---|
| **Voigt（主分析）** | `bm_core.fit(K=2, alpha=0.5, zeta_fixed=1.0, **sigma=None**, init_values=None)`——**生产默认：自由采样 σ + 默认初始化，原样运行** |
| Voigt（结构对照） | 同上，但 `sigma = 逐点 2%·\|Z\|` 固定 —— 与 nested 完全同口径，只用于把"σ 口径"的影响分离出来 |
| Nested（参照） | `bm_top.fit_top(branch="capacitive", layers=2)`，**数据驱动初值**（`Rs=min\|Z\|`、`R1=0.5·zmax`、`Q=\|Z\|(f_ref)`、`n=0.9/0.9/0.6`） |
| 噪声底 | 数据 vs **真值拓扑正演**（`Q_ours=Q_data/ω_ref^n`，`ω_ref=2π√(f_min·f_max)`） |
| 噪声 | 见上两行；nested 用逐点固定 `σ_j = 2%·\|Z_j\|`（实虚同值），不采样 σ |
| 预算 | `standard`（warmup 2000 / samples 1000 / 2 chains / ta=0.98），两族同口径 |
| 种子 | `seed=0`，全部样本同一 seed |

**K 的口径与已知限制**：主分析固定 `K=2`（此前 bmdrt 在该族选中的值）。
这不是完整的 bmdrt 路径（bmdrt 还含 K 选择），故结论只能写成
"**K=2 固定下的生产族失效率**"。K 选择稳定性另用 6 条子集检查，单独报告，不进主比例。

**初始化敏感性（单独一栏，不进主比例）**：凡主分析 `unusable` 的样本，
用**数据驱动初值**把 Voigt 再跑一次，只用于判定"是不是初始化问题"。这一列**不得**混入
"生产默认 Voigt 失效率"——否则等于替生产路径换了初值。

## 3. 判据（冻结）

先用两条定**结果能不能用**：

- `R̂_max > 1.05` → 采样未收敛
- `divergences > 0` → 采样有分歧

`ESS_min < 100` 只记警告，不作判据（ESS 小使后验中位不稳，但不足以否定整条）。

在**结果可用**（`R̂ ≤ 1.05` 且 `div = 0`）前提下，定义

```
ratio = rms_rel(拟合) / rms_rel(真值正演)
```

| 判定 | 条件 | 依据（跑之前就有的观察） |
|---|---|---|
| `structural_mismatch` | `ratio > 1.5` | nested 6 条实测 0.72–0.99；钝化 voigt 1.8–2.9 → 1.5 落在两者之间 |
| 其中 `runaway` | `ratio > 5.0` | 涂层已见一条 7.5× |
| `param_unidentifiable` | `ratio ≤ 1.5` 且 `max_k \|θ̂_k/θ_k − 1\| > 0.50` | nested 钝化 0.92–1.23（8–23%）、涂层 R2 2.37×（137%）→ 50% 落在中间 |
| `ok` | 其余 | — |

判定顺序（互斥，先到先得）：
1. `unusable_sampling`（R̂ 或 div）
2. `structural_mismatch`（ratio > 1.5）
3. `param_unidentifiable`（ratio ≤ 1.5 但单参数 > 50%）
4. `ok`

**参数误差口径**：逐参数 `|θ̂/θ − 1|`，θ̂ 取后验中位；另单独记录组合量 `Rs+R1`。

## 4. 主指标与区间

- 主比例 = `structural_mismatch / 60`（含 `runaway`）。
- 95% 区间用 **Wilson**；60 条时约 ±13pp。因是分层抽样（12 格各 5，格在总体中近似等大），
  等权平均即为总体比例的近似无偏估计；此处区间**不**含"12 格划分本身"的模型不确定性。
- 同时报：`unusable_sampling` 比例、`param_unidentifiable` 比例、`ratio` 的分布（不只二分类）。

## 5. 不做

- 不替 Voigt 换初始化进主分析；不改 K 选择口径；不回改判据。
- 不扫满 1000 条；若 `ratio` 显示明显参数区域依赖（某格 5 条全 >1.5 或全 <1.2），才扩到 100 条。
- 不动 `bmdrt.py` / 先验 / 阈值 / 面板契约；nested 结论仍为 `exploratory`。
- 本轮不产出任何"验收通过"陈述。

## 7. 修订登记

### M1（跑前修订，2026-11-13 16:28）

**起因**：首版口径把 Voigt 的 σ 也固定成逐点 2%（为与 nested 同口径）。跑满 14/60 条后
发现 `unusable_sampling` 占 8/14，且这些样本的 `R̂ = 15.7–100.7`、`ESS = 1` —— 不是"边缘未收敛"，
而是某条链整条卡死。而**生产 bmdrt 的 σ 是自由采样的**（`sigma=None`，且 `rms/σ≈1` 正是由此而来）。
固定 σ 让似然面变陡，初始化偏差更容易卡住，等于**把"该口径下的采样困难"记到"voigt 失效"账上**。

**修订**（在 60 条全部完成前、且此前**未计算过任何比例估计**；只看到 14 条的逐条 R̂/ratio，未看分层汇总）：

1. 主分析改为 `sigma=None`（**自由 σ，真生产口径**）；
2. 另跑一份 `sigma=2%` 固定的同一模型，作**结构对照**，只用于分离"σ 口径"的影响；
3. 判定（§3）不变，但 `ratio` 与 `R̂` **一律取自由 σ 那一份**；
4. `floor` 与 `ratio` 都是纯几何量（不依赖 σ），两种口径下可比，无需重算 floor。

**这条修订不改变任何阈值**（`RHAT_MAX`/`RATIO_STRUCT`/`RATIO_RUNAWAY`/`PARAM_TOL` 全部原样），
只纠正"主分析测的是谁"。首版跑出的 14 条作废重跑（口径不同，不可拼接）。

### M2（跑中修订，2026-11-13 16:49；跑完 6/60 后、仍**未算过任何分层汇总比例**）

**起因两件事，都不是"结果不好看"：**

1. **进程死机。** 跑 6 条后整个 Python 进程死于
   `LLVM ERROR: _beginthreadex failed: 系统资源不足`。这是同一进程内反复 `C.fit`
   累积 JAX/XLA 线程句柄所致，与判据、模型、数据都无关。
2. **敏感性栏的方法写错了。** §2 原文要求"用**数据驱动初值**把 Voigt 再跑一次"，
   但首版代码实现的是"**加力重采样**（`warmup=4000, seed=1`，初值不变）"。
   这两件事在 §0 里恰恰是**要区分的两种机制**：加力重采样只能排除"warmup 不够"，
   排除不了"默认初始化落在坏区域"。实现与预注册不符，属代码错，不是判据变。

**修订：**

1. **执行方式**：调度进程每跑 4 条就起一个新子进程（`--worker --limit 4`），
   子进程结束即交还线程句柄。**不改拟合口径、不改预算、不改种子**。
   代价是每条多约 4 s 的 JAX import 开销。
2. **敏感性栏改为真·数据驱动初值**：新增 `voigt_init(f, Z)`，只用 `f` 与 `|Z|`
   构造初值（`R_inf=min|Z|`、`W=(zmax−zmin)/2`、`tau` 在窗口内均匀铺 K 个、
   `phi=0.8`、`v=1/K`、`σ=2%·mean|Z|`），**不读真值**。
3. **空间约定**（踩过的坑，写死）：`bm_core.fit` 走
   `init_strategy=init_to_value`，`initialize_model` 会先 `transform_fn(invert=True)`，
   故必须传**约束空间（物理值）**；`bm_top.fit_top` 走 `init_params=`，那条才是无约束。
   首版按无约束传，直接 `Cannot find valid initial parameters`。
4. **已跑的 6 条**：主分析（`voigt_prod`/`voigt_fix2`/`nested`/`verdict`）口径未变，
   **保留不重跑**；只对其中 `unusable_sampling` 的 4 条用 `--backfill-sens` 补算敏感性栏，
   旧值转存到 `sensitivity_old_warmup` 备查。重写前自动备份 `results.jsonl.bak_<ts>`。

**这 6 条已经说明敏感性栏现在有判别力**（只作说明，不作比例）：

| 3 | 14.51 | unusable | 1.0027 | **7.36** |

#### M3-b 一项诊断：`R̂` 爆表的机制是**标签置换 + 抵抗脊**，不是数值失败

10 条（跨格轮转抽）用生产配置复跑并记录逐链后验（`mode_diag.py`）：

- 8/10 条里，存在一个分量落在 `ln τ ≈ +7.1 ~ +7.7`（τ≈1200–2200 s）。而
  `1/f_min = 159 s`，先验上界 `l1 ≈ 8.5` ⇒ **该分量跑到窗口之外**，退化成串联恒电阻，
  与 `R_inf` 构成一条**抵抗脊**（谁当那个常数是可互换的）。
- 各链把同一个后验的**不同标签实现**分开拟合（chain0 `[7.39, −5.57]`、chain1 `[−5.57, 7.39]`）。
  逐样本内把 `ln τ` 排序后重算 R̂：**中位 18.49 → 8.04**；其中 **4/10 降到 ≤1.05**
  （纯标签问题），6/10 仍 >1.05（真多峰：不同链选了"哪个分量当常数"）。至少 2 个模式的 7/10。
- `K=3` 对照（4 条逃逸样本，`k3_check.py`）：三条链**都**把恰好一个分量放在 `ln τ ≈ 7.4–8.2`，
  只是放在不同槽位；排序后 R̂ **107.6 → 1.00、47.5 → 1.00、19.2 → 1.04、16.6 → 1.03**。
  ⇒ 提高 K 不消除逃逸分量，"`R̂` 爆表"基本全是置换对称，**不是采样器坏了**。

**因此 `unusable_sampling` 这一列不能读作"Voigt 采样失败率 76.7%"**，它的含义是
"**该后验在本口径下存在多标签/多表示分支**"。`Z(f)` 对置换不变，所以 `ratio`/`acf`
仍然有效；**但分量级参数（单个 `tau`/`W`/`pi`）不可用**。

#### M3-c §2 敏感性栏的补充读数

46 条 `unusable` 全部补算了数据驱动初值：**46/46 恢复收敛**，恢复后 `ratio` 1.66–8.52
（中位 3.85），**46/46 都 >1.5**。另在 2 条上换 3 个 seed 复跑：`ratio` 7.54/7.46/5.25、
4.26/4.30/4.26 —— 同一分支内 `ratio` 稳定，波动只出现在换分支时。

⇒ 结论：**"生产 Voigt 在这个族上会失败"是系统性的**，`unusable` 与 `structural_mismatch`
是**同一件事的两个层面**（先被多重表示卡住，换初值后落到 `ratio>1.5`），
不是两种独立失败机制。§0 的三分法在本族上退化为：`init_failure` 几乎不存在
（46/46 只是被初值挡在门外），`structural_mismatch` 才是主因。

#### M3-d 已知缺陷（未修，留给下一轮）

- `results.jsonl` 里 `sigma_re_at` 恒为 `NaN`：代码判 `"sigma_re" in sv`，而位点名是
